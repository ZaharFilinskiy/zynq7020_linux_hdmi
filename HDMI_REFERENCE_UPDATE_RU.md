## Что изменено

| Сигнал | Вывод FPGA |
|---|---|
| Генератор 50 МГц | K17 |
| Сброс, активный ноль | M20 |
| HDMI clock P/N | H16 / H17 |
| HDMI data0 P/N | D19 / D20 |
| HDMI data1 P/N | C20 / B20 |
| HDMI data2 P/N | B19 / A20 |
| HDMI output enable, постоянная 1 | H18 |

Положительные выводы, clock/reset/enable взяты из XDC эталона. Отрицательные — из его `hdmi_encoder_top_io_placed.rpt`, без предположений о парных контактах. TMDS_33 для HDMI, LVCMOS33 для clock/reset/enable.

`hdmi_enable` (xlconstant, значение 1) добавлен непосредственно в Block Design и подключён к `hdmi_out_en`. PS, DDR, VDMA и исходные периферийные блоки сохранены.

Clock Wizard настроен как в рабочем примере: вход 50 МГц, запросы 74.2 и 371.25 МГц. Полученные параметры MMCM совпадают: DIVCLK=1, MULT=22.25, делители 15 и 3. Реальные частоты 74.166667 и 370.833333 МГц, отношение точно 1:5. При растре 1650x750 частота кадров около 59.93 Гц. Имена проводов `74p25` в эталоне не означают точную частоту 74.25 МГц.

Изображение 1280x720: восемь цветных полос, нижние 64 строки — шахматный узор 32x32, рамка 2 пикселя. Генератор `axis_hdmi_source` остаётся Module Reference в Block Design. Размеры теперь параметры H_ACTIVE/V_ACTIVE; TEST_PATTERN=1 не требует SDK, Linux, DDR или инициализации PS.

`axis_hdmi_video`: 1280/110/40/220 по горизонтали, 720/5/5/20 по вертикали; положительные HS/VS. Намеренно сохранён корректный формирователь синхронизации: в `vga_sync.v` эталона HS ошибочно формируется по H_FRONT_PROCH вместо H_SYNC_TIME, а вертикальный счётчик преждевременно сбрасывает последнюю строку. Эти ошибки не перенесены. RGB, DE и синхросигналы имеют одинаковую задержку. Порядок байтов Digilent — R,B,G, как в эталоне.

Сброс передатчика сохраняет прежнюю безопасную схему: после сброса платы и захвата MMCM, с синхронным снятием сброса в пиксельном домене. В эталоне aRst просто привязан к нулю.

## Запуск

Открыть `zynq_linux.xpr` в Vivado 2018.3. Hardware Manager → Open Target → Auto Connect → Program Device. Выбрать `hdmi/export/vivado_test/hdmi_test_pattern.bit`. SDK не нужен. Это загрузка в FPGA по JTAG; после отключения питания требуется повторная загрузка.

## Повторение изменений и сборка

Скрипт `hdmi/tcl/apply_corrected_reference.tcl` обновляет существующий Block Design и его HDL wrapper. `build_test_pattern.tcl` собирает bitstream и проверяет setup/hold; `test_pattern.tcl` проверяет четыре полных кадра, перезапуск после reset, цвета каждого пикселя, HS/VS/DE, устойчивость AXI при остановках и режим внешнего потока.

Старые файлы SDK/FSBL/simplefb оставлены как исторический результат. Они рассчитаны на 640x480 и не являются готовой конфигурацией Linux для этой сборки 1280x720. Для следующего этапа потребуется согласованно обновить framebuffer, VDMA и Device Tree. Новое дерево устройств на этом этапе не создавалось.

Файл `hdmi/constraints/hdmi_lab10.xdc` сохраняет историческое имя, но содержит только новую распиновку. Для восстановления текущего BD используйте `design_1_hdmi_generated.tcl`; старые add_hdmi/add_test_pattern — история предыдущих этапов, запускать их поверх текущего проекта не нужно.
