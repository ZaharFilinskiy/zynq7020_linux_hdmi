# Проверки HDMI

Дата: 03.10.2026. Проверялось в Vivado/SDK 2018.3 на этом компьютере.

## Аппаратная сборка

- Block Design: validation успешно.
- Synthesis, placement, routing, write_bitstream: успешно.
- WNS **+4,617 нс**, TNS 0; WHS **+0,026 нс**, THS 0.
- WPWS +3,000 нс. Нет нарушений заданных временных ограничений.
- Нет внутренних endpoints без ограничения maximum delay, нет регистров
  без тактового сигнала.
- Фактические частоты: AXI 100 МГц, pixel 25,2 МГц, serial 126 МГц.
- Использование: 1744 LUT (3,28%), 2392 регистров (2,25%),
  5 BRAM36 tiles (3,57%), 0 DSP.

Отчёт DRC не пуст: **0 Errors / Critical Warnings уровня DRC**, но 19 Warning
и 1 Advisory. Это 18 REQP-1839 (асинхронный reset/control RAM внутри
штатного VDMA/AXI IP), RTSTAT-10 (внутренний сигнал без routable loads),
REQP-181 (WRITE_FIRST у внутренней FIFO RAM). Они сохранены в `export/drc.rpt`.
Никакие DRC severity не понижались. Проверка аппаратных сбросов и длительный
прогон на плате остаются необходимыми для окончательной приёмки.

Отчёт methodology: LUTAR-1 внутри штатного AXI protocol converter;
TIMING-18 для прежнего GPIO T12 без output delay; XDCB-5 про эффективность
запроса в оригинальном rgb2dvi XDC. Эти предупреждения не скрывались.
Vivado также пишет Common 17-741 о недоступном пользовательском Tcl Store
и Designutils 20-3303 про IOPAD; сборка успешно использует установленный IP.

Первая промежуточная версия с разными тактами внутри VDMA имела отрицательный
recovery slack. Она заменена: VDMA полностью на 100 МГц, crossing вынесен
в AXIS Clock Converter. Финальные отчёты относятся к исправленному варианту.
Широкие false paths/clock groups для сокрытия нарушения не добавлялись.

## Симуляция собственного RTL

XSim проверил 8 полных кадров 800×525 = **3 360 000 тактов**:

- RGB и перестановку RBG перед rgb2dvi;
- DE, отрицательные HSync/VSync, blanking;
- backpressure при остановке приёма в blanking;
- потерю TVALID в середине кадра;
- преждевременный TLAST;
- преждевременный TUSER;
- восстановление на следующей границе кадра;
- очистку флага ошибки и выходов при reset.

Результат: **PASS**. Тест — `tests/tb_axis_hdmi_video.sv`.
Это поведенческая проверка видеоблока, не полная симуляция DDR/PS/монитора.

## Программная часть

- FSBL с `HdmiDisplayInit` компилируется и линкуется SDK 2018.3.
- Standalone `hdmi_smoke.elf` собран; Bootgen 2018.3 создал
  `BOOT_HDMI_TEST.bin` (4 182 600 байт) из FSBL + bitstream + smoke test.
- HDF содержит bitstream и актуальную PS/PL-конфигурацию.
- SHA-256 bitstream внутри HDF совпадает с экспортированным `.bit`;
  HDF аппаратной платформы SDK совпадает с финальным HDF Vivado.
- `linux/fb_test.c` проверен ARM Linux GCC из SDK с
  `-std=c99 -Wall -Wextra -Werror -O2`; компиляция без предупреждений.
  Для запуска собрать его заново Buildroot toolchain под фактическую libc.

## Что не подтверждено

- Физический сигнал на мониторе и корректность разводки конкретной платы.
  Выбрана распиновка Lab10, работоспособность которого подтвердил пользователь.
- Загрузка Linux, наличие `/dev/fb0`, работа fbcon/getty.
- Совместимость фрагмента DTS с отсутствующим полным деревом и конкретным ядром.
- Поведение отсутствующего U-Boot относительно framebuffer, FCLK и PL reset.
- Захват камеры, звук, EDID и другие разрешения — вне первого этапа.

Отдельный диагностический BOOT-образ нужен, чтобы проверить плату независимо
от отсутствующей Linux-сборки. Его наличие не означает, что он уже испытан.
